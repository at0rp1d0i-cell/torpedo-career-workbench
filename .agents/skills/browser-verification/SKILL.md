# 浏览器验证与授权 Skill

## 默认策略

浏览器不是普通数据同步的默认验证工具。静态 HTML、JSON、CLI 输出和脚本行为优先使用文件读取、DOM / 文本断言、窄测试或实际 CLI 冒烟验证。

## 需要浏览器时

如果任务涉及以下任一项，Agent 在启动浏览器前必须主动询问用户本次是否授权浏览器验证：

- 需要确认实际视觉布局；
- 需要确认交互、筛选、折叠或导航行为；
- 需要操作只能通过网页完成的用户界面。

询问应说明：验证目标、是否会打开外部页面、是否会访问用户已登录状态，以及预计使用哪种隔离方式。不能把“浏览器验证是规则要求”当作默认授权。

## 隔离边界

- 用户未明确授权时，禁止使用 Browser relay、用户现有 Chrome 或共享浏览器。
- 获得授权后，使用显式 `app.path` 启动 Agent 自己拥有的隔离 Chromium 实例；不要依赖 Browser 工具默认选择，因为全局 `browser.relay` 设置可能自动接管用户浏览器。
- 首次 `open` 只打开空白页或本地验证入口，并检查返回结果。若结果包含 `on relay`，立即释放该会话且不得继续导航或点击；随后告知用户当前无法保证隔离。
- 不得假设 relay 空闲；当前工具不提供可靠的 session 所有权或互斥锁查询。
- 如果只能使用 relay，必须再次明确告知可能干扰其他 session，并等待用户对 **本次 relay 使用** 的明确授权；普通“允许浏览器验证”不自动包含 relay 授权。
- 验证结束后关闭 Agent 创建的 tab / 进程；不关闭、不导航、不改写用户已有 tab。

## 结果纪律

- 浏览器验证只证明实际打开并检查的页面行为，不替代 CLI、脚本或文档校验。
- 纯数据输入变化不要求视觉验证；只有渲染逻辑或交互逻辑变化才默认进入浏览器验证候选。
